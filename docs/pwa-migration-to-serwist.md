# PWA Migration: next-pwa → Serwist

## Summary

Successfully migrated from the abandoned `next-pwa` package to **Serwist**, the actively maintained successor to Workbox PWA.

## Migration Date

November 26, 2025

## What Changed

### Removed
- ❌ `next-pwa@^5.6.0` (abandoned since 2022)
- ❌ Old service worker configuration in `next.config.js`
- ❌ Legacy Workbox generated files (`workbox-*.js`)

### Added
- ✅ `serwist@^9.2.3` - Modern service worker library
- ✅ `@serwist/next@^9.2.3` - Next.js integration plugin
- ✅ New service worker source: `src/app/sw.ts`
- ✅ Updated Next.js config with Serwist plugin

## Files Modified

### 1. `package.json`
- Removed: `next-pwa`
- Added: `serwist`, `@serwist/next`

### 2. `next.config.js`
- Replaced `withPWA()` wrapper with `withSerwist()`
- Simplified configuration (runtime caching moved to service worker file)

### 3. `src/app/sw.ts` (NEW)
- Complete service worker implementation using Serwist API
- Maintains all previous runtime caching strategies:
  - Google Fonts (stylesheets & webfonts)
  - Firebase API endpoints
  - Local API routes
  - Images (all formats)
  - Google profile images
  - Firebase Storage images
  - Navigation pages
  - Static resources (scripts & styles)
- Includes SKIP_WAITING message handler for update prompts

### 4. `public/sw.js`
- Automatically generated by Serwist during build
- Replaces old `next-pwa` generated service worker

## Caching Strategies Preserved

All previous caching strategies were maintained:

| Resource Type | Strategy | Cache Name | TTL |
|--------------|----------|------------|-----|
| Google Fonts (stylesheets) | CacheFirst | google-fonts-stylesheets | - |
| Google Fonts (webfonts) | CacheFirst | google-fonts-webfonts | 1 year |
| Firebase API | NetworkFirst | firebase-api | 1 day |
| Local API routes | NetworkFirst | api-cache | 1 hour |
| Images | CacheFirst | images | 30 days |
| Google profile images | CacheFirst | google-profile-images | 7 days |
| Firebase Storage images | CacheFirst | firebase-images | 30 days |
| Navigation pages | NetworkFirst | pages | 24 hours |
| Static resources | CacheFirst | static-resources | 30 days |

## PWA Components Status

All existing PWA components continue to work without modification:

- ✅ `PWAInstallPrompt.tsx` - Install prompt functionality
- ✅ `PWAUpdatePrompt.tsx` - Update notifications (uses SKIP_WAITING message)
- ✅ `PWAStatus.tsx` - PWA status indicators
- ✅ Service worker message handling in `serviceManager.ts`

## Service Worker Registration

Serwist automatically injects service worker registration code during the Next.js build process. No manual registration script needed.

**Note:** For static export (current configuration), the service worker registration is automatically included in the generated HTML.

## Build Output

The build process now shows:
```
✓ (serwist) Bundling the service worker script with the URL '/sw.js' and the scope '/'...
```

Service worker is automatically generated at: `public/sw.js`

1. **Active Maintenance** - Serwist is actively developed and maintained
2. **Modern API** - Cleaner, more intuitive API compared to next-pwa

4. **Improved Performance** - Optimized service worker generation

## Known Issues

None currently. All functionality preserved from previous implementation.

## Rollback Plan

If issues arise, rollback by:

1. Restore `next-pwa`:
   ```bash
   npm install next-pwa@^5.6.0
   ```

2. Revert `next.config.js` to use `withPWA()`

3. Remove `src/app/sw.ts`

4. Restore old runtime caching config in `next.config.js`

5. Rebuild the application
